Artifact Description

The artifact I selected is the Grazioso Salvare Rescue Animal Dashboard that I originally created in CS 340 Client/Server Development. The application uses Python, Dash, Pandas, Plotly, Dash Leaflet, and MongoDB to work with animal shelter records from the Austin Animal Center dataset. The original dashboard allowed a user to select different rescue categories, filter the animal records, view breed information in a chart, and display the selected animal on a map.

I selected this artifact because it gave me a useful starting point for showing how an existing application can be improved instead of building a completely separate program. The original project already worked with a large collection of animal records, so it was a good fit for adding an algorithm that could evaluate those records and make the results more useful.

Justification and Algorithms/Data Structures Enhancement

The main improvement for this milestone was changing the dashboard from only filtering animals to also evaluating and ranking rescue candidates. In the original version, an animal either matched the MongoDB filter or it did not. That was useful for narrowing down the dataset, but it did not provide any way to compare candidates that met different parts of the desired rescue criteria.

I added a separate candidate_scoring.py module that calculates a suitability score for an animal based on the selected rescue type. The algorithm evaluates characteristics such as breed, sex, and age and assigns weighted points when an animal matches the preferred characteristics. The resulting records are then filtered so animals with a score of zero are removed and the remaining candidates are sorted from the highest suitability score to the lowest. The dashboard displays the calculated Suitability Score with the animal records so the ranking is visible to the user.

This enhancement demonstrates algorithms and data structures because the program now performs more than a database lookup. Animal records are represented with Python dictionaries and processed as a list of records. The scoring function evaluates the values stored in each dictionary, calculates a numeric score, and the ranking function organizes the resulting list using that score. I also made sure the ranking process does not modify the original animal records. Instead, the algorithm works with copies when it adds the suitability score.

There were design trade-offs involved in this approach. A weighted scoring system is easy to understand, test, and adjust, which makes it appropriate for this application. It is also more flexible than requiring every animal to exactly match every condition. At the same time, the weights are rules defined by the application rather than a predictive model, so the scores should be treated as a way to organize candidates rather than as an absolute judgment. This was a reasonable trade-off because the goal of the enhancement was to demonstrate algorithmic decision making while keeping the behavior transparent.

I also expanded automated testing as part of this work. The project now has 24 passing tests. The tests cover rescue-filter behavior, candidate scoring and ranking, visualization behavior, and mocked database CRUD interactions. The database tests use mocks instead of changing the real MongoDB collection. This also responds to instructor feedback to continue expanding automated testing to visualization and database interaction behaviors.

Reflection on the Enhancement Process

The biggest thing I learned from this enhancement was the difference between filtering data and actually ranking it. The original dashboard could find animals that matched a set of MongoDB conditions, but that did not mean it was evaluating which candidates were the strongest matches. Adding a scoring algorithm required me to think about how multiple characteristics could be represented numerically and how the results should be sorted in a useful way.

One challenge was making sure the new algorithm worked correctly inside the existing dashboard without breaking the features that were already working. I kept the scoring logic in a separate module and tested it independently before relying on it in the notebook. I also tested that ranking did not change the original records. During integration, I found that the notebook could continue using an older imported version of the scoring module after the Python file had been changed. Restarting the notebook kernel and running all cells reloaded the updated module and confirmed that zero-score candidates were being removed correctly. The lowest remaining viable score in the tested Water Rescue results was 20.

Testing became a larger part of the enhancement than it was in the original project. The automated test suite grew to 24 passing tests. In addition to checking the new scoring and ranking behavior, I added tests for the visualization functions and mocked MongoDB CRUD operations. This helped me address the instructor feedback while also showing me how automated tests can protect existing functionality while an application continues to change.

Overall, this enhancement improved the usefulness of the artifact without replacing its original purpose. The dashboard still allows the user to filter, inspect, visualize, and map animal records, but it can now also evaluate viable rescue candidates and place them in a meaningful order. That makes the application a stronger example of my ability to apply algorithms and data structures to an existing software system.

After receiving instructor feedback, I improved the documentation of my candidate scoring algorithm to explain why each characteristic receives its assigned weight. Breed receives 50 points because it is the primary matching characteristic in the rescue profiles, while age receives 30 points and sex receives 20 points. These weights are design choices intended to make the original filtering criteria more useful for ranking candidates, rather than scientifically validated measures of rescue ability. Documenting this distinction helped me better understand the importance of making algorithmic decisions transparent and explaining the reasoning behind them.
