These responsibilities require me to investigate problems across different devices and systems rather than assuming every issue has a single cause. Being able to adapt to the audience helps people work toward the same result.

My coursework reinforced these lessons. Software Engineering and Broader Coursework

The Computer Science program exposed me to several languages and development environments, including Python, Java, Kotlin, C++, JavaScript, SQL, and MongoDB. Working with different tools helped me become more adaptable and better at identifying the approach that fits a particular problem.

For example, my Android mobile application coursework involved building an inventory application with user authentication, database storage, and inventory management functions. That project required me to consider the relationship between the interface, application logic, and stored information. In computer graphics, I used C++ and OpenGL to work with three-dimensional objects, camera movement, lighting, and rendering. These projects were different in purpose, but both required careful debugging, incremental development, and attention to how separate components interact.

My CS 499 capstone gave me the opportunity to apply those lessons to an existing project rather than starting over. I selected the Grazioso Salvare Rescue Animal Dashboard from CS 340, a Python and MongoDB application for exploring animal shelter records. For the software design and engineering enhancement, I separated database operations, rescue filters, and visualization into focused modules. I also improved configuration handling, input validation, error handling, and automated tests. These changes made the application easier to understand and gave me a stronger foundation for further enhancements.

Algorithms, Data Structures, and Design Trade-Offs

My algorithms and data structures enhancement changed the dashboard from a tool that only filters animals into one that can also rank potential rescue candidates. I developed a Python scoring module that evaluates breed, age, and the sex preferences defined in the rescue profiles. It assigns up to 100 points, removes records with a score of zero, and sorts the remaining candidates from highest to lowest score. The algorithm uses lists and dictionaries and works with copies of records so the source data is not changed during scoring.

This enhancement helped me think more carefully about trade-offs. A weighted scoring system is transparent, testable, and relatively easy to change, but the weights are design choices rather than a scientifically validated prediction of rescue performance. Breed receives 50 points, age 30, and sex 20 based on how the original rescue profiles prioritize those characteristics. After instructor feedback, I expanded the documentation to explain that reasoning and its limitations. This experience showed me that a useful algorithm must be understandable and defensible, not just capable of producing a result.

Databases, Testing, and a Security Mindset

For the database enhancement, I moved breed-count calculations into MongoDB aggregation pipelines, added methods for creating and inspecting indexes, and expanded validation and automated testing around database interactions. I kept index administration separate from routine dashboard startup so configuration changes could be performed deliberately. These improvements showed me how decisions about where processing occurs can affect application design and maintenance. I implemented and tested the index-management methods, but I have not claimed measured performance improvements from deploying indexes to a live database.

Testing became an important part of my capstone work. By the end of the database enhancement, the project had 30 passing automated tests covering filtering, scoring, visualization, and mocked database operations. Using mocks for database tests allowed me to check application behavior without creating, changing, or deleting real shelter records. I learned that tests are not only for proving a new feature works; they also help protect functionality as a project evolves.

Security is especially relevant to my career goals. In the capstone, I used environment-based database configuration rather than placing credentials directly in source code, and I improved validation and error handling. My field technician experience with network support and VPN-connected devices gives me practical exposure to the infrastructure that organizations rely on. I do not view that experience as a substitute for dedicated cybersecurity training, but it helps me understand why secure configuration, reliable operations, and careful handling of information matter.
